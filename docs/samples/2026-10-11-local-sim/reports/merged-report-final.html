名詞解釋
VU（虛擬使用者）壓測工具模擬的一位使用者。本壓測中一個 VU 會跑完一整段對話（開場問候 ＋ 8～11 則訊息，中間有思考時間）。
每秒請求（req/s）每秒送出的聊天 API 呼叫數。規劃的「每秒處理量」看送出量與成功量兩個數字。
p50／p95／p99把所有回應時間由快到慢排序：p50 是中間那一筆（一半的請求比它快）；p95 是第 95% 那一筆（只有 5% 比它慢）；p99 同理。p95、p99 代表「慢的那一群使用者」的體驗。
avg（平均）所有回應時間的平均。容易被少數極慢的請求拉高，所以判定以 p95 為主。
錯誤率（5xx ＋ timeout）系統錯誤（HTTP 5xx）與逾時佔全部請求的比例，是規劃定義的錯誤率。
業務錯誤不是系統錯誤，但回應不符合預期（例如 4xx）。另外列出，不算進錯誤率。
HTTP 429超過每日聊天次數上限被拒絕。依規劃出現就立即停止並檢查設定。
持續期間／爬升期間每個加壓階段先花幾分鐘把流量爬升到目標（爬升），再維持一段時間（持續）。各階段判定只看持續期間。
參考門檻證券方文件的參考值（FAQ p95 ≤ 10 秒、業務查詢 p95 ≤ 5 秒、錯誤率 ≤ 0.5%）。正式門檻在 Baseline 實測後共同確認。
task（壓測機）Cloud Run Jobs 平行執行的一台壓測機，各送 1/N 的流量。本報告把所有 task 的原始數據合併計算。
dropped_iterations壓測機來不及開始新對話而跳過的次數。大於 0 代表實際送出的負載低於設定，是壓測機不足，不是受測系統的問題。

趨勢圖

怎麼看藍線是壓測機送出的請求量，綠色虛線是成功的量。兩條線重疊代表系統跟得上；綠線開始低於藍線，代表有請求失敗。背景色塊是各加壓階段（深色＝持續期間，淺色＝爬升期間）。
怎麼看p50 是一半的請求在這個時間內完成；p95 是 95% 的請求在這個時間內完成（最慢的 5% 不算）；p99 同理。看加壓時這三條線是否明顯往上爬：p50 穩定但 p99 上升，代表少數請求開始卡住；三條一起上升，代表整體變慢。超過 30 秒的請求會被負載平衡器直接回錯誤。
